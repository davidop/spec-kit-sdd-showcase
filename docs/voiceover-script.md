# Guion de locución · borrador de producción (es-ES)

**Duración objetivo:** 90 segundos. Ajustar tras grabación y cronometraje real. Voz masculina natural, tono de arquitecto de software. Este guion no implica que se hayan ejecutado los pipelines o las pruebas mostradas.

| Intervalo | Locución |
|---|---|
| 00–06 | Una nueva cobertura en un seguro de hogar puede afectar a más de un repositorio. |
| 06–18 | Con desarrollo guiado por especificaciones, primero definimos el comportamiento esperado: cuándo se activa la cobertura, cómo se calcula la prima y qué debemos comprobar. |
| 18–36 | Spec Kit 1.4.1 incorpora novedades en su ecosistema, incluidas extensiones comunitarias. Pero cuidado: que exista una extensión multi-repositorio en el catálogo no significa que la herramienta orqueste automáticamente todo nuestro código. |
| 36–52 | En nuestro ejemplo, React presenta la opción de daños por agua. La API de .NET calcula el suplemento y devuelve el desglose. Terraform solo cambia si hay una necesidad real de infraestructura u observabilidad. |
| 52–69 | GitHub Copilot, Claude Code y Codex son tres alternativas para trabajar sobre estas especificaciones. No estamos simulando una coordinación autónoma entre ellos. La revisión técnica sigue siendo nuestra responsabilidad. |
| 69–82 | Después vienen los cambios, la pull request, los tests, el análisis de seguridad y la revisión humana. En pantalla verás una simulación del flujo, no una ejecución real. |
| 82–90 | La clave no es generar más código: es reducir ambigüedad y mantener el control. Microsoft MVP, David Oliva. |

## Notas de producción
- Los importes de la cotización son ficticios.
- No incluir frases de «tests superados» sin ejecución verificada.
- Contrastar detalles de la versión con el changelog oficial antes de locutar.
- Generar subtítulos desde la locución final, no ajustar la voz a subtítulos aproximados.
