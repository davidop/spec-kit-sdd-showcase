1. Consultar release notes oficiales del tag 1.4.1 en el repositorio oficial de GitHub Spec Kit.
2. Separar explícitamente **capacidades oficiales**, **extensiones de terceros** y **patrones de arquitectura propuestos**.

4. No presentar terminales, tests, pipelines o PR simulados como evidencia real.
5. No afirmar que una regla de negocio exige modificar Terraform salvo que exista cambio de infraestructura justificado.
6. Verificar licencias de logos, música, voz y recursos audiovisuales antes de publicar.
7. Comprobar duración, resolución, audio, subtítulos y safe areas en el render final.
